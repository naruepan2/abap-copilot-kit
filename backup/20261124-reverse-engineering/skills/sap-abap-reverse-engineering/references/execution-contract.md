# Observable Execution Contract

State machine:
`PRECHECK -> ROOT_RESOLUTION -> INPUT_EVIDENCE_INVENTORY -> AUTHORIZED_READ_CHECK -> PLAN_FREEZE -> DEPENDENCY_DISCOVERY -> SOURCE_READING -> SEMANTIC_LINEAGE -> COMPANIONS -> DEPENDENCY_RECONCILIATION -> GAP_CLOSURE -> SELECTED_DELIVERY -> CANONICAL_NAME_LINT -> FINAL_ACCEPTANCE -> SCRATCHPAD_CLEANUP`.

Publish a short plan, wave/checkpoint metrics, gap list, and final verification result. Do not publish chain-of-thought. Apply the same investigation state machine for all delivery modes; technical-specification generation is conditional on `TECHNICAL_SPECIFICATION` or `BOTH`, while `CHAT_ANALYSIS` uses chat-summary validation and creates no artifact.

`PRECHECK` closes only when every decision the mode needs is settled: delivery mode, intensity profile, language, and — for `TECHNICAL_SPECIFICATION`/`BOTH` only — template, output format, destination directory, exact filename, and existing-file handling. `PLAN_FREEZE` must not happen while any of these is still open; resolving format or destination after the plan is frozen forces rework. `CHAT_ANALYSIS` skips the template, format, and path decisions entirely.

For large, multi-branch, or timeout-prone work, use the optional `scalable-analysis.md` playbook after bounded reconnaissance. Keep one coordinator-owned manifest/queue and use checkpoints between bounded waves. Sub-agents are optional workers only for evidenced independent branches and only when their relevant read access is actually available; never assume they inherit SAP destination, client, authorization, tools, or shared state. A worker may report branch findings, not global completeness. If a budget/timeout requires stopping, return the last validated checkpoint and residual queue as partial; do not lower scope or evidence requirements. Use a JSONL scratchpad only when needed to persist large intermediate state, and follow exact-path cleanup/verification rules.

`INPUT_EVIDENCE_INVENTORY` identifies prompt attachments and explicit workspace paths, records their provenance, and routes dependency artifacts to reconciliation without asking the user to repeat provided information. `AUTHORIZED_READ_CHECK` confirms the target is explicit and the requested reads are permitted using available evidence; it is not permission to probe write capabilities. Discover package, object type, dependencies, and companions through safe reads where possible; ask only for facts that cannot safely be discovered. Object-type strategy guidance is advisory: an absent or ambiguous mapping does not prevent generic discovery or queue expansion. `SELECTED_DELIVERY` creates/validates a Technical Specification only for document modes; chat-only uses response validation and creates no artifact.

Required queue fields: discovered, queued, expanding, expanded, verified terminal (root-kind appropriate), resolved implementation, cycle, user boundary, standard/foreign boundary, provider limited, unresolved dependency, inventory-only relation, and excluded non-dependency. For every supplied dependency-artifact row/path, also preserve its source row/node/edge identifier, hierarchy level when applicable, parent occurrence, canonical object ID when applicable, relation/operator, and reconciliation disposition. Operator nodes are structural, not objects.

Every closed node requires a close reason and evidence ID. Queue-empty alone is not completion.
